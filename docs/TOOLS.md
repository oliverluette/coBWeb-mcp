# Tool reference

Object types are given as BW TLOGO-style codes (`ADSO`, `IOBJ`, `TRFN`, …; see the README).
Every tool validates its arguments strictly and answers in compact text. Errors name the cause
and, where it helps, the next step.

## bw_search

Find objects by technical name or description, or list one level of an InfoArea.

| Parameter | Meaning |
|---|---|
| `query` | name or text pattern with `*`, e.g. `ZSALES*`, `*revenue*` |
| `types` | restrict to these object types |
| `info_area` | list the objects in this InfoArea (without `query`) |
| `limit` | maximum hits |
| `source_system` | only DataSources of this source system |

## bw_read

Read one object.

| Parameter | Meaning |
|---|---|
| `type`, `name` | the object (`source_system` for a DataSource) |
| `detail` | `summary` (default), `full` (every property) or `raw` (backend document, for debugging) |
| `part` | one section of a large object, e.g. `fields`, `keys`, `rules`, `routines`, `steps`, `layout`, `filter`, `cells`, `roles`, `planning`, `hierarchies`, `entities:<pattern>`, `variant:<VARIANT>` |

A name with `*` lists matching objects for types that have no search entry (`ROLE`, `HIER`).

## bw_context

How an object is connected.

| Parameter | Meaning |
|---|---|
| `relation` | `dataflow`: sources and targets with the transformations and DTPs between them; `where_used`: objects that reference it |
| `direction` | `up`, `down` or `both` |
| `depth` | how many hops to follow |

## bw_describe

The spec format `bw_write` expects for one type and action (`create` or `update`): fields,
allowed values, defaults and an example. Call it once per type before the first write.

## bw_write

Create, update or delete objects and activate them in the same call.

| Parameter | Meaning |
|---|---|
| `objects` | list of `{action, type, name, source_system, spec}`; `action` is `create`, `update` or `delete` |
| `package` | development package (default `$TMP`; must be allowed by `COBWEB_ALLOWED_PACKAGES`) |
| `transport` | transport request, needed outside `$TMP` on systems with transport recording |
| `activate` | activate after saving (default `true`) |
| `validate_only` | check specs, names, limits and dependencies against BW without writing |

The server sorts the objects by dependency, locks, saves, activates and unlocks; objects that
depend on a failed one are skipped. A create of an object that exists becomes an update; an
update merges the given spec into the object; the same spec again reports `unchanged`. Deletes
are checked for where-used and run in the order of use. The name of a transformation or DTP is
generated by BW: omit it on create and identify the object by source and target.

Example: a characteristic, a key figure and a DataStore object in one call:

```json
{
  "objects": [
    {"action": "create", "type": "IOBJ", "name": "ZREGION",
     "spec": {"kind": "characteristic", "description": "Region", "info_area": "ZSALES", "length": 4}},
    {"action": "create", "type": "IOBJ", "name": "ZAMOUNT",
     "spec": {"kind": "key_figure", "description": "Amount", "info_area": "ZSALES", "data_type": "AMOUNT", "currency": "EUR"}},
    {"action": "create", "type": "ADSO", "name": "ZSALES01",
     "spec": {"description": "Sales", "info_area": "ZSALES", "fields": ["ZREGION", "ZAMOUNT"], "keys": ["ZREGION"]}}
  ]
}
```

## bw_activate

Check or activate existing inactive objects, e.g. DTPs that a change deactivated.
`check_only=true` runs the consistency check without activating. The answer lists the objects
an activation deactivated.

## bw_data

Read business data (needs `COBWEB_ALLOW_DATA=true`).

| Action | Meaning |
|---|---|
| `query` | run a query, or read a provider (ADSO, HCPR) directly |
| `preview` | rows of a DataSource (`source_system` required) |
| `values` | values of a characteristic (`search`, `provider`) |

For `query`:

| Parameter | Meaning |
|---|---|
| `rows`, `columns` | characteristics or structures by name; the others go to the free area. Without them the layout of the query applies. |
| `filter` | per characteristic `{field, values}`, `{field, selections: [{op, low, high, exclude}]}` (`op`: `eq`, `ne`, `between`, `gt`, `ge`, `lt`, `le`) or `{field, nodes}` for text nodes of the display hierarchy; `exclude`, `internal` (values are internal keys) |
| `variables` | `{NAME: "A"}`, `"A..B"` (interval) or `"A,B"` (list) |
| `collapse`, `expand` | hierarchy nodes to collapse or expand in the result, by key or text |
| `offset`, `max_rows` | paging; the answer says whether more rows follow |
| `with_statistics` | runtime and HANA statistics of the call |

Where BW applies a selection differently from the request (e.g. an excluded hierarchy node as
included), the answer lists it under "Not applied".

## bw_monitor

Read-only monitoring.

| `what` | Meaning |
|---|---|
| `chain_status` | last run of every process chain |
| `chain_runs` | runs of one chain (`name`) |
| `chain_run` | steps and messages of one run (`name`, `id` = log id) |
| `requests` | load requests of a provider (`name`, `storage`, `target_type`) |
| `request` | one request (`id` = TSN) |
| `remodeling` | remodeling requests of a provider; `id` = rule for details |
| `query_stats` | executions of a query or provider |

Filters: `status`, `since`, `until`, `limit`.

## bw_run

Runtime actions (need `COBWEB_ALLOW_EXECUTE=true`; objects must lie in allowed packages and
InfoAreas).

| Action | Meaning |
|---|---|
| `run_dtp` | run a DTP (`name`) |
| `start_chain` | start a process chain once, now (`name`); `wait_seconds` up to 600 |
| `activate_request` | activate a request of an ADSO (`name`, `id` = TSN) |
| `delete_request` | delete a request (`id`) or every request (`all_requests`) of a target |
| `run_remodeling` | run a remodeling rule (`name` = provider, `id` = rule, `mode`) |
| `push_data` | write records into an ADSO with write interface (`records: [{FIELD: value}]`) |

## bw_transport

| Action | Meaning |
|---|---|
| `list` | changeable transport requests (`all_users`, `include_released`, `with_objects`) |
| `create_task` | a task in a request for a user |
| `assign` | assign objects to a package (and a transport request) |
| `move` | move objects to another InfoArea |

## bw_system

| Action | Meaning |
|---|---|
| `profile` | release, platform, enabled types, safety settings and naming rules |
| `unlock` | release a lock this server still holds after an aborted change (`type`, `name`) |

## Structured results (`COBWEB_STRUCTURED=true`)

For programs that call coBWeb without a language model, e.g. an application that draws the data
flow. Off by default: then `tools/list` and every answer stay exactly as described above.

With the flag, `bw_search`, `bw_read`, `bw_context` and `bw_system` offer an `outputSchema`, and
each of their answers carries `structuredContent` next to the unchanged text. The size limit
`COBWEB_MAX_RESULT_CHARS` applies to the text only; structured data is complete. The flag grants
no rights: reading and writing are still governed by the other flags. Do not set it for model
clients: the schemas cost tokens in every request, and some clients pass `structuredContent` to
the model.

Every answer is an envelope `{"schema": "cobweb.<kind>/<version>", "data": …}`:

| Schema | Tool | Content |
|---|---|---|
| `cobweb.dataflow/1` | `bw_context` (dataflow) | `root`, `direction`, `depth`, `objects` and `flows` (transformations, DTPs), each with `sources` and `targets` as references, `unresolved` |
| `cobweb.where_used/1` | `bw_context` (where_used) | `root`, `hits` with `side` (`up`, `down`, `other`) and, for flows, `flow` with both ends |
| `cobweb.search/1` | `bw_search` | `hits`, `total`, `returned`, `truncated`, `notes` |
| `cobweb.system/1` | `bw_system` (profile) | release, platform, `cobweb_version`, safety settings as booleans |
| `cobweb.hcpr/1` | `bw_read` HCPR | head, `composition`, `inputs` with mappings, `fields`, `joins` |
| `cobweb.trfn/1` | `bw_read` TRFN | head, `runtime`, `source`, `target`, `routines` (class, method), `rules`, fields |
| `cobweb.dtpa/1` | `bw_read` DTPA | head, `mode`/`mode_raw`, `source`, `target`, `transformation`, `filter`, `semantic_group` |
| `cobweb.object_head/1` | `bw_read` ADSO, IOBJ, RSDS, TRCS with `part="head"` (or `"keys"`) | `status`, `description`, `info_area`, `package`, `keys` |
| `cobweb.unstructured/1` | any of the four | the call succeeded, but this type or option has text only (e.g. `detail="raw"`); `data` is `null` |
| `cobweb.error/1` | any of the four | `isError`; `data` = `{kind, message, hint}` |

HCPR, TRFN and DTPA return the whole model whatever `part` or `detail` the text shows.

Rules for the data:

- **References:** `ref` is `TYPE:NAME`, `RSDS:NAME:SOURCE_SYSTEM` for DataSources and
  `IOBJ:NAME:attr`, `:text` or `:hier` for the parts of an InfoObject. Query elements are named by
  their type (`QUERY`, `VARIABLE`, …), not `ELEM`. Every object also has `type`, `name` and,
  where it applies, `source_system` and `part`.
- **Status:** `active`, `inactive`, `revised` or `new`; any other BW value is `unknown`, with the
  BW value in `status_raw`. Objects without a status (source systems) have `null`.
- **Fields:** `snake_case`, numbers as numbers, no formatting. New optional fields keep the
  version; renamed or removed fields raise it.
- `total` of `bw_search` counts the hits BW returned.
